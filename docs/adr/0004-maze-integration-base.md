## 背景

A课程工程与B的Peripheral Lab无共同祖先。B已导入相同A模型并交付地图/BFS，需进入UI阶段；不能将两套main和配置整分支硬合并。

## 备选

| 方案 | 优点 | 代价 |

| A：B的Lab/LVGL工程作为最终基线，保留A模型与B地图/UI | 现有显示/触摸入口和外设参考齐全，较快联调 | 大量音频/蓝牙等依赖，镜像大，告警与资源需评估 |

## 决策与后果

王若豪已在这次集成基线问题中明确选择A：以B的Lab/LVGL工程为最终基线，保留现有A模型、B地图和显示/触摸入口。选择依据为现有显示触摸入口有利于较快联调，接受当前依赖多、镜像较大及告警需要评估的代价；不把这些优点说成新的实物性能已通过。

已由B的943e762创建并发布 `feat/maze-integration` 为共同集成分支，远端核对为943e762d30ed6bee64c21cd19ae5e92b6c7e38ea；原main仍1672326，B原分支未改动。A旧course_starter分支保留历史/文档参考，不将两边无共同祖先的工程整分支硬合并。

B继续UI功能分支并向集成分支提交改动；A从集成分支开展IMU/校准、request_id与唯一刷新调度适配。B的UI不得另建游戏推进timer或复制模型；生产适配仍未实现。当前本地集成工作副本为 `build/maze-integration`，与原A工作区隔离，不覆盖其未提交OS材料。

基线选择当时地图4项证据仍缺；学生随后另补地图4项PASS截图，现已与模型24项分别确认通过。UI、真实IMU和整机通关仍未验证。依赖裁剪、配置调整或新功能先有需求/测试和SDK依据，未授权为消告警随意删依赖。
