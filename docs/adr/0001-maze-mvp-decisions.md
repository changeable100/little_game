# ADR-0001：体感迷宫首版玩法、调度与范围

- 状态：成员 B 已选择；A 已交付 MAZE_CONTRACT_VERSION v1 说明；源码核对及 A/B 联评待完成
- 日期：2026-10-17
- 决策人：成员 B（姓名待补）

## 背景

任务书要求在功能实现前明确玩法、调度与首版范围。当前本地仓库已经有 LVGL 主循环和独立的鹈鹕自行车游戏，但没有迷宫模块。A 已提供 MAZE_CONTRACT_VERSION v1 接口/时序说明，进一步明确球半径 0.20 格、每轴速度上限 3 格/s、单次 dt 上限 100 ms、同一 UI 线程和唯一刷新入口由 A 管理。文档提及的契约/模型源码及 77b15d3 提交暂未进入当前工作副本或可见 GitHub main。

## 决策

1. **玩法**：选择倾斜控制连续滚动小球。
2. **调度**：选择在现有 UI 线程按周期推进有界的一步游戏计算，IMU 由受保护快照提供。
3. **首版范围**：选择一张固定关卡；包含起点/终点、开始、暂停/继续、通关计时与重开，不做多关卡选关。

以上选择由成员 B 在 2026-10-17 明确提出；A 的 v1 说明已作为 B 文档的接口基准，但真实公共头文件和模型源码仍待交付核对，因此不宣称源码集成完成或双方已通过代码联调。

## 考虑过的备选

| 决策 | 备选 | 选择理由 |
|---|---|---|
| 玩法 | 倾斜触发按格移动 | 连续小球更直接呈现板卡倾斜体感；A 契约说明球半径 0.20 格并限制速度和单步 dt，但正式通道仍须结合真实模型核验 |
| 调度 | 独立游戏任务，通过有界消息/快照通信 | A 契约说明由 A 管理唯一刷新入口并在同一 UI/模型线程推进，减少队列与跨线程协调；生产集成尚未进入当前工作副本，不能宣称已验证 |
| 关卡 | 多关卡及选关 | 单关卡更快验证首次贯通并降低地图/资源/验收范围 |

## 后续动作与影响

- 成员 B 直接使用 A 的 `maze_contract.h`，不得复制公共类型；待 A 把头文件、模型源码和自检提交提供到本工作副本后逐项核对字段/错误语义。
- 依据 A 的 v1 说明，球半径为 0.20 格、每轴速度不超过 3 格/s、单次推进 dt 不超过 100 ms、暂停不累计 elapsed_ms；地图尺寸与像素缩放仍需 A/B 共同审核。
- 本 ADR 记录成员 B 的选择，不代替成员 A 的评审签署。
