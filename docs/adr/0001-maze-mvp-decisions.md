# ADR-0001：体感迷宫首版玩法、调度与范围

- 状态：玩法/调度/范围与 16×16 蛇形地图已选择；地图/BFS 主机实现和模型回归通过；UI、真机验证待完成
- 日期：2026-10-17
- 决策人：成员 B（姓名待补）

## 背景

任务书要求在功能实现前明确玩法、调度与首版范围。当前 B 工程已有 LVGL 主循环和独立的鹈鹕自行车游戏。A 分支 `feat/req-301-maze-model` 与 B 分支无共同 Git 祖先，且包含不同的 RGB 工程入口；为避免覆盖 B 工程，用户已确认只选择性导入 A 的公共契约、模型和自检源文件。模型约束包括球半径 0.20 格、每轴速度上限 3 格/s、单次 dt 上限 100 ms；生产刷新入口、UI 和 IMU 尚未集成。

## 决策

1. **玩法**：选择倾斜控制连续滚动小球。
2. **调度**：选择在现有 UI 线程按周期推进有界的一步游戏计算，IMU 由受保护快照提供。
3. **首版范围**：选择一张固定关卡；包含起点/终点、开始、暂停/继续、通关计时与重开，不做多关卡选关。
4. **固定地图**：学生于 2026-10-17 确认采用提案中的 16×16 蛇形单通道地图；B 以只读静态数组实现，并提供四邻接 BFS 自检。

以上选择由成员 B 在 2026-10-17 明确提出；A 模型主机 24 项自检、B 地图自检及确认地图上的连续模型回归通过，固件构建通过；这不能替代真机验证，也不代表 UI、IMU 或整机联调完成。

## 考虑过的备选

| 决策 | 备选 | 选择理由 |
|---|---|---|
| 玩法 | 倾斜触发按格移动 | 连续小球更直接呈现板卡倾斜体感；A 契约说明球半径 0.20 格并限制速度和单步 dt，但正式通道仍须结合真实模型核验 |
| 调度 | 独立游戏任务，通过有界消息/快照通信 | A 契约规定由 A 管理唯一刷新入口并在同一 UI/模型线程推进，减少队列与跨线程协调；当前仅有纯逻辑模型，生产刷新集成仍待验证 |
| 关卡 | 多关卡及选关 | 单关卡更快验证首次贯通并降低地图/资源/验收范围；蛇形地图结构简单，能覆盖交替转角与边界走廊 |
| 固定地图 | 带分支/环路的复杂地图 | 16×16 蛇形单通道实现简单、可用四邻接 BFS 清楚验证；随后以模型验证连续碰撞，不把拓扑连通误当可玩性 |

## 后续动作与影响

- 成员 B 直接使用已导入的 A `maze_contract.h`，不得复制公共类型；A/B 集成时继续核对字段与错误语义，不合并 A 分支的旧工程入口或构建骨架。
- 依据 A 的 v1 说明，球半径为 0.20 格、每轴速度不超过 3 格/s、单次推进 dt 不超过 100 ms、暂停不累计 elapsed_ms；确认地图已通过 host 模型连续碰撞回归，仍需真机体验证据；UI 像素缩放仍需实现和物理验证。
