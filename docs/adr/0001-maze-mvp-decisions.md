# ADR-0001：体感迷宫首版玩法、调度与范围

- 状态：成员 B 已选择；待成员 A 共同评审接口和集成边界
- 日期：2026-10-17
- 决策人：成员 B（姓名待补）

## 背景

任务书要求在功能实现前明确玩法、调度与首版范围。当前本地仓库已经有 LVGL 主循环和独立的鹈鹕自行车游戏，但没有迷宫模块；公共快照、操作意图与关卡契约仍需成员 A 起草。

## 决策

1. **玩法**：选择倾斜控制连续滚动小球。
2. **调度**：选择在现有 UI 线程按周期推进有界的一步游戏计算，IMU 由受保护快照提供。
3. **首版范围**：选择一张固定关卡；包含起点/终点、开始、暂停/继续、通关计时与重开，不做多关卡选关。

以上选择由成员 B 在 2026-10-17 明确提出；成员 A 的碰撞、快照和集成契约尚未评审，故暂不宣称双方已冻结或实现。

## 考虑过的备选

| 决策 | 备选 | 选择理由 |
|---|---|---|
| 玩法 | 倾斜触发按格移动 | 连续小球更直接呈现板卡倾斜体感；相较按格移动，碰撞与通道宽度风险更高，需要 A 明确半径和边界规则 |
| 调度 | 独立游戏任务，通过有界消息/快照通信 | UI 线程周期推进更简单，减少队列和跨线程协调；前提是 A 证明每步有界且不阻塞 |
| 关卡 | 多关卡及选关 | 单关卡更快验证首次贯通并降低地图/资源/验收范围 |

## 后续动作与影响

- 成员 A 起草唯一公共契约；双方确认状态、快照、意图、地图类型、坐标单位与失败语义后再写功能代码。
- 成员 A 提供碰撞半径、速度/步进边界和计时/暂停语义；成员 B 据此定关卡格数和通道净宽。
- 本 ADR 记录成员 B 的选择，不代替成员 A 的评审签署。
