# ADR-0001：体感迷宫的模块边界与游戏/UI 调度

- 状态：已采纳方案 A（2026-10-17，王若豪确认）
- 日期：2026-10-17
- 决策人：王若豪（项目负责人）；另一位成员姓名待补，不代记其个人确认
- 协助：Codex / GPT-6
- 关联需求：REQ-201、REQ-202、REQ-203、REQ-204、REQ-205、REQ-206、REQ-207、REQ-208（均为草案）

## 背景

两人准备开发体感迷宫，学生要求先梳理协作边界并交接另一位成员任务。建议王若豪负责 IMU、游戏规则与集成，另一成员负责界面和关卡；模型与显示不能各维护一份互相矛盾的状态。线程安排尚未选择，必须结合 SDK 例程、单步计算耗时与资源实测再确认。

## 备选方案

| 方案 | 优点 | 代价和前提 |
|---|---|---|
| A：UI 线程周期执行有界游戏步进，IMU 提供受保护快照 | 游戏和显示同步关系简单，初版并发较少 | IMU I/O 等耗时操作不能进入 UI 路径，须验证步进/绘制不阻塞，线程开销与周期待定 |
| B：独立游戏任务，界面发送有界意图并读取复制快照 | 游戏任务与 UI 生命周期相对独立 | 须定义队列容量/忙、状态同步、过期数据、线程资源和退出恢复，开发验证成本更高 |

两种方案都保持单一模型写入者、UI 所属线程独占 LVGL、不可变地图共享、明确失败返回。项目接口详见 `../guides/体感迷宫-双人协作与界面关卡任务书.md`，目前为提案。

## 决策

学生已回复“审阅完毕，选择方案 A，现在开始做”，采纳 A：游戏状态只由 UI 所属线程推进，IMU 由独立采样方提供复制快照。所有游戏 API 只由同一线程调用；不在采样线程或 shell 中直接修改运行中的模型。初版避免引入独立游戏任务的队列与跨任务状态同步成本；单步必须有界，无 I/O、无等待、无动态分配，真实耗时仍须上板测量。

首个增量先交付公共契约、纯逻辑模型与启动板上自检，不创建 B 的界面和正式关卡。自检使用独立临时模型和标记为测试的地图，执行完回到原 RGB 例程，不将测试输入充当真实 IMU。

## 后果与待办

按任务书方案 A 采用连续滚动小球及首版单张固定地图，记录于 ADR-0002。B 可以按已提供的公共头文件开展界面/关卡开发；布局与正式地图由 B 提交评审。UI/触摸/IMU 效果和步进耗时尚未实测；模型自检必须由学生上板取得 PASS/FAIL 证据。
