## 3. 模块职责与数据流

```text
src/maze_levels.c/.h   B：固定只读地图、地图结构/可达性验证（已实现）
src/maze_levels_selftest.c/.h B：正式地图、断路图和非法地图启动自检（已实现）
src/maze_ui.c/.h       B：LVGL 页面、地图绘制、按钮、快照呈现（待实现）
src/maze_contract.h    A/B：唯一公共状态/快照/意图/地图契约（已接入）
src/maze_game.c/.h     A：运动、碰撞、状态、计时、意图处理（已接入）
src/maze_selftest.c/.h A：隔离模型自检；当前入口启动时调用
```

公共结构定义只放已接入的 A `maze_contract.h`。B 不复制或另定义同名快照/事件类型。MAZE_CONTRACT_VERSION v1 快照包含 `run_id/revision/level_id/state/input_status/error_code/ball_x/ball_y/ball_radius/elapsed_ms`；坐标单位为格、原点左上且 y 向下；地图为 1～16 行列的 `uint8_t` 行优先数组，PATH=0/WALL=1，结构和数组需长生命周期。B 的 UI 仅读取值拷贝，不保留调用者临时指针。

### 固定关卡与可达性检查

学生已确认采用 `docs/maze-ui-proposal.md` 的 16×16 蛇形单通道地图作为首版唯一关卡。B 的 `maze_levels.c/.h` 提供静态 `maze_level_t` 和长生命周期只读 cells；接口提供默认关卡、结构安全检查后的四邻接可达性判定。BFS 使用固定大小 `visited[256]` 与 `queue[256]`，按行优先索引遍历，不动态分配、不递归；非法结构直接判不可达。`maze_levels_selftest.c/.h` 在启动时验证正式地图结构/可达、断路图不可达、仅对角相邻图不可达和畸形地图拒绝；主机测试通过。A 的 `maze_game_level_check()` 负责契约结构约束，B 的 BFS 负责拓扑可达性。TC-203 已用受控主机输入将 A 模型沿所有走廊中心线推进至终点格并进入 WON，且逐步检查球体未与墙重叠；该模拟不替代板上体验证据。

接口定义动作 `action/expected_run_id/request_id`，sink 同步、非阻塞且在 UI/模型同一线程调用。请求号由接入层提供并保持跨局单调递增。当前方案没有动作队列，因此没有队列忙返回值；B 按 `MAZE_OK/INVALID/WRONG_STATE/STALE/EXHAUSTED` 处理，并在接受后重新读快照。已接入的契约/模型代码来自 A 分支模型版本 `77b15d3`，实际文件位于 `src/maze_contract.h` 与 `src/maze_game.c/.h`；生产 UI 调度与 IMU 接入仍未实现。

已按用户选择和 A 契约说明采用同一 UI 线程的有界 step/快照顺序。A 管理唯一刷新入口、单调毫秒时钟和 IMU 快照；约 20 ms 是目标而不是测得帧率；每次 RUNNING step 的 dt 必须为真实时间差且不超过 100 ms，暂停/非运行状态须重置或更新锚点，不可将暂停时间混入下一步。B 只渲染与提交动作，不在按钮/绘制回调执行传感器 I/O、碰撞、计时或胜负判断，不建立第二个游戏定时器。完整时序尚无生产集成实现或实测。
