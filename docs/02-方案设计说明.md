## 3. 模块职责与数据流

```text
src/maze_levels.c/.h   B：固定只读地图、地图结构/可达性验证
src/maze_ui.c/.h       B：LVGL 页面、地图绘制、按钮、快照呈现
src/maze_contract.h    A 起草、A/B 共同冻结：唯一公共状态/快照/意图/地图契约
src/maze_game.c/.h     A：运动、碰撞、状态、计时、意图处理
```

公共结构定义只放 `maze_contract.h`。B 不自行定义一份同名快照或事件类型；接口签名、错误语义、地图格编码、坐标单位和版本字段等待 A 的第一版契约并经双方确认。B 的 UI 仅读取快照，不保留调用者临时指针；按钮向 A 提供的非阻塞 sink 提交意图，UI 只在后续快照确认后显示已完成。

已选择调度为 UI 线程周期调用一次有界模型步进，并读取受保护 IMU 快照。B 负责不在渲染/按钮回调中执行传感器 I/O、碰撞、时间累计或胜负判断；游戏推进入口和唯一刷新时钟由 A 集成。此约定不得在 B 模块另建游戏任务或第二个推进定时器。

## 4. B 的界面与地图提案状态

- 目标屏幕 390 × 450；`docs/maze-ui-proposal.md` 给出初版区域划分与页面流转。
- 地图维度、像素格宽、最窄通道和小球绘制半径尚未冻结。必须等 A 提供碰撞半径/安全间隙后再定图，避免格点连通但连续小球无法通过。
- 地图验证至少覆盖尺寸/数据长度、起终点合法且不同、通路连通；连续碰撞净宽由 A 审核，不能用 UI 裁剪代替逻辑边界检查。
- 屏幕方向与传感器方向映射由 A 的输入/游戏模块负责；B 按公共契约坐标绘制，不对 IMU 再做一套方向变换。
