## 3. 模块职责与数据流

```text
src/maze_levels.c/.h   B：固定只读地图、地图结构/可达性验证
src/maze_ui.c/.h       B：LVGL 页面、地图绘制、按钮、快照呈现
src/maze_contract.h    A 起草、A/B 共同冻结：唯一公共状态/快照/意图/地图契约
src/maze_game.c/.h     A：运动、碰撞、状态、计时、意图处理
```

公共结构定义只放 A 维护的 `maze_contract.h`。B 不复制或另定义同名快照/事件类型。A 提供的 MAZE_CONTRACT_VERSION v1 说明规定快照包含 `run_id/revision/level_id/state/input_status/error_code/ball_x/ball_y/ball_radius/elapsed_ms`；坐标单位为格、原点左上且 y 向下；地图为 1～16 行列的 `uint8_t` 行优先数组，PATH=0/WALL=1，结构和数组需长生命周期。B 的 UI 仅读取值拷贝，不保留调用者临时指针。

契约说明定义动作 `action/expected_run_id/request_id`，sink 同步、非阻塞且在 UI/模型同一线程调用。请求号生成器由 A 适配层统一提供。当前方案没有动作队列，因此没有队列忙返回值；B 按 `MAZE_OK/INVALID/WRONG_STATE/STALE/EXHAUSTED` 处理，并在接受后重新读快照。上述定义来自用户提供的说明文档；实现对应的共享头文件与模型源码仍未出现在当前分支，须在接入前与 A 的实际代码逐项核对。

已按用户选择和 A 契约说明采用同一 UI 线程的有界 step/快照顺序。A 管理唯一刷新入口、单调毫秒时钟和 IMU 快照；约 20 ms 是目标而不是测得帧率；每次 RUNNING step 的 dt 必须为真实时间差且不超过 100 ms，暂停/非运行状态须重置或更新锚点，不可将暂停时间混入下一步。B 只渲染与提交动作，不在按钮/绘制回调执行传感器 I/O、碰撞、计时或胜负判断，不建立第二个游戏定时器。完整时序尚无生产集成实现或实测。

## 4. B 的界面与地图提案状态

- 目标屏幕 390 × 450；`docs/maze-ui-proposal.md` 给出约 16×16、20 px/格（320×320 地图）候选及页面流转；像素尺寸仍待 A 联评。
- A 契约说明规定 `ball_radius=0.20` 格，直径 0.40 格；UI 必须按快照半径绘制，采用统一比例 `s`，圆心 `(ox+ball_x*s, oy+ball_y*s)`，不能以绘图舍入修改模型逻辑。
- 地图维度上限 16×16、行优先索引及格值已由契约说明给出；B 自检仍需覆盖尺寸/数据长度、端点和四邻接可达性。A 的模型检查不做 BFS，通路净宽和实测可玩性仍需验证。
- 屏幕方向与传感器方向映射由 A 的输入/游戏模块负责；B 按公共契约坐标绘制，不对 IMU 再做一套方向变换。
