5. 若出现ERROR，保持现场，慢慢发送`maze_diag status`。回传下面两行（若有）以及随后diag/imu/gyro/input四行，不必立即重启。首次TIMING错误自动输出这两行，status也会重显冻结记录，不受你输入速度影响。

```text
[maze:timing] run=... gap=... render=... prep=...
[maze:loop] run=... handler=... wait=... valid=... rv=...
```

所有时间字段单位ms。gap是发生故障时相对于控制器anchor的实际推进差；render是前次runtime渲染回调的墙钟耗时；prep是当前tick开始至取得样本后的耗时，若故障由动作结算触发则填0。handler是上次完整lv_timer_handler耗时，wait是其后实际等待（包括调度延迟），不是请求睡眠时长。valid=1说明已有完整主循环窗口，rv=1说明已有渲染测量，否则对应值缺测，0不等于已证实无耗时。

handler包含渲染/显示/其他LVGL工作，与render和gap有重叠，不能相加。它们是相邻已完成窗口的观测，不是CPU分析；单靠handler-render也不能精确认定显示flush。status可能重显上一局最后故障，看run区分，不把它认成本局新故障；错误后age增长仍是旧样本年龄。正常运行不每20ms打印诊断，周期status仍每500ms。
