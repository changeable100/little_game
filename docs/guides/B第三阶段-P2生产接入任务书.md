## 4. 启动状态：先区分两种 READY

`maze_runtime_init_status()` 是 A 新增的只读接口，只在 main/LVGL 线程查询，不能从后台线程轮询。main 已先 runtime_init 再创建菜单；B 不重复 init。

| 启动状态 | 值 | 产品行为 |
|---|---:|---|
| NOT_INITIALIZED | 0 | 游戏入口不可用，显示尚未初始化 |
| READY | 1 | 允许进入生产页面，后续按钮仍依据模型快照 |
| SELFTEST_FAILED | 2 | 入口不可用，显示自检失败 |
| LEVEL_FAILED | 3 | 入口不可用，显示关卡初始化失败 |
| QUEUE_FAILED | 4 | 入口不可用，显示运行时队列初始化失败 |
| TIMER_FAILED | 5 | 入口不可用，显示运行时时钟初始化失败 |

启动 READY=1 表示资源已建立；游戏快照 READY=0 表示尚未开始。它们是两个枚举，不能混用，也不能把启动 READY 显示成校准完成。启动失败时保留可查看的首页/说明和明确原因；不能展示一个看似已能开始的生产按钮。

`maze_runtime_cancel_startup()` 仅供 A 在菜单创建失败时回收启动资源。B 的 BACK、页面关闭及重进都用正常动作和 detach，不能调用它。

## 5. 生产打开与快照回送

按下面顺序实现，失败路径也要落入测试：

1. 查询启动状态，仅 READY 允许生产打开；拒绝重复打开同一页面。
2. 创建页面和适配上下文，再 `maze_runtime_attach(render_wrapper, context)` 绑定一次。
3. attach 成功后可立即 snapshot 获取当前画面；首次快照成功前禁用游戏操作。之后由 runtime 的20ms唯一入口在 revision 改变时回调。进入页面不隐式 START，不重置已有局面。
4. render_wrapper 只复制需要保留的快照值，再调用 `maze_ui_render()`；传入快照/level 的指针仅回调期间借用，不缓存临时指针，不在回调中递归 action/detach。
5. attach 失败时，只释放本次未绑定的 UI；**不能无条件 detach**，否则可能清掉已有页面的绑定。attach 成功后再发生读取/创建失败，才解除自己持有的绑定并清理。

UI 使用快照球位、半径、时间和状态；关卡数据用传入的同一份只读地图。保持390×450及已验证安全边距，坐标单位是格，像素圆心按格宽换算后减半径；不要把串口的千分之一格当像素。显示时间用 `elapsed_ms/1000`，20ms应显示0s，暂停/WON不自行加时。

## 6. 按钮动作：统一的发送步骤

每次按钮事件都在 LVGL 线程执行：

```c
/* displayed 是该页面已经复制并显示的快照，不是临时指针。 */
maze_action_t a = {
    .action = requested_action,
    .expected_run_id = displayed.run_id
};
maze_result_t rc = maze_runtime_next_request(&a.request_id);
if (rc == MAZE_OK)
    rc = maze_runtime_action(NULL, &a);

/* 即使 rc 失败也重读：PAUSE 在结算期间可能先到 WON/ERROR。 */
maze_snapshot_t actual;
maze_result_t read_rc = maze_runtime_snapshot(&actual);
/* 仅在 read_rc==MAZE_OK 时使用 actual；按 rc 与真实快照更新画面。 */
```

运行时 action 的 context 必须为 NULL；render 的 context 可以是页面上下文，两者不要混淆。UI 自己的 -100 段错误码与 `maze_result_t` 分开。

| 结果 | 处理 |
|---|---|
| OK=0 | 重读真实状态；START 接受后可能是 CALIBRATING，也可能因采样资源不可用进入 ERROR |
| INVALID=-1 | 给出参数/动作错误提示，重读；不猜测模型仍在原状态 |
| WRONG_STATE=-2 | 按真实状态刷新；例如重进后尚无新鲜样本，RESUME 可被拒绝 |
| STALE=-3 | 放弃该旧意图并显示当前局面，不能换新run自动重发 |
| EXHAUSTED=-4 | 停止产生新游戏意图，提示重启应用/设备；不能自造编号或回绕 |

失败动作的已申请ID也不重复使用。快速点击和延迟事件不能借用新局编号冒充旧意图。

## 7. 六态控件与文案

| 快照状态 | 显示 | 游戏控件 |
|---|---|---|
| READY | 准备开始、起点、真实时间 | START可用，PAUSE/RESUME禁用；BACK可用 |
| CALIBRATING | 保持平放、正在校准 | START/PAUSE禁用；保留BACK，不用UI定时器假装校准成功 |
| RUNNING | 真实球位和用时 | PAUSE、RESTART、BACK可用 |
| PAUSED | 暂停、冻结用时 | 同一按钮改为RESUME；RESTART/BACK可用 |
| WON | 通关、冻结最终用时 | RESTART/BACK可用，PAUSE禁用 |
| ERROR | 输入/关卡/计时原因和恢复提示 | BACK可用；RESTART的实际结果仍按返回值及新快照处理 |

RESTART可在游戏终态恢复为新一局校准；READY可只保留START，CALIBRATING可禁用重复RESTART以减少误操作。实际启用规则在需求/TC中明确，不能只换按钮文字。非法地图/坐标/未知枚举继续安全提示、隐藏球；保留P1的校验。状态提示使用已配置字体可显示的文字。

生产路径接通后更新首页、说明页及游戏页的“PREVIEW/Static preview/controls not enabled”文案，确保说明与当前行为一致。模拟测试页仍明确标识模拟。

## 8. BACK、临时关闭和销毁

- **显式BACK**：提交BACK并重读；成功后detach，再销毁页面，显示独立首页。BACK被拒绝时保持可解释的失败反馈，不能直接假称模型已READY。
- **临时释放/重建**：只detach再释放UI，保留模型局面，不隐式BACK/RESTART。运行中detach会结算并暂停、请求停止采样；重进按真实快照显示PAUSED，等待新鲜样本后才可RESUME。
- **菜单整体销毁/外部删除/失败回滚**：都必须先消除runtime持有的UI引用；B须覆盖现有`home_deleted`、`maze_menu_destroy`和页面删除事件等路径，关闭函数应幂等，避免重复发送BACK或释放上下文。
- detach先清除回调引用，但停止采样由后台完成；不能主动操作Lab工作槽或抢占其他任务。关闭后仍可保留应用级runtime timer，它不是页面泄漏。

不能在对象已释放后才试图detach，也不能用destroy回调再访问已释放的上下文。快速退出/重新进入必须在生产适配测试中覆盖。
