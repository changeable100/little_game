### P1：先实现六态渲染（B）

读取真实 `maze_snapshot_t` 和同一 `maze_level_t`，显示小球、状态、时间、错误；扩展当前 READY-only 校验。非法坐标、未知枚举、地图不匹配时安全提示；不能为支持 ERROR/WON 而撤掉数据有效性检查。

小球中心坐标以格为单位，左上原点、右为 x 正、下为 y 正；20px/格时中心换算为 `MAP_X + ball_x*20` / `MAP_Y + ball_y*20`，对象左上角再减半径。球半径读取快照，当前为 0.20 格；不从串口千分之一格数值直接当像素。保留已板测的屏幕安全边距，真实页面确认后更新 PREVIEW 相关文案。

### P2：接入真实快照与按钮（B 实现，A 联评）

| 状态 | 必须显示 | 建议控件行为（最终按联评写入用例） |
|---|---|---|
| READY | 准备开始、起点、0s | START 可用；BACK 回首页 |
| CALIBRATING | 保持平放、正在校准 | START/PAUSE 不可用；保留 BACK，避免误连续重开 |
| RUNNING | 实际球位与累计时间 | PAUSE、RESTART、BACK 可用 |
| PAUSED | 暂停、冻结时间 | 主按钮显示 RESUME；RESTART/BACK 可用；恢复失败需实际反馈 |
| WON | 通关与冻结的最终用时 | RESTART、BACK 可用；不继续显示可暂停 |
| ERROR | 明确输入/计时/关卡错误及恢复提示 | BACK 可用；RESTART 是否能恢复以返回值和新快照为准 |

进入迷宫只创建页面并绑定快照，不隐式 START；开始由按钮触发，用户可以先放平板子。实际 START 接受后是 CALIBRATING，不能按钮一按就显示 RUNNING。

UI 适配流程依据现有 runtime：

1. 页面创建成功，绑定一次 `maze_runtime_attach(render, context)`；绑定失败需释放本次 UI 或保留明确失败页。
2. render 包装器只调用 UI 渲染；收到的指针仅回调期间有效，需要缓存就复制快照值。回调内不递归 action/detach。
3. 按钮事件从当前已显示快照取 `expected_run_id`，调用 `maze_runtime_next_request` 分配非零、跨局递增 ID，再调用 `maze_runtime_action(NULL, &action)`。
4. 每次操作后，无论返回成功或失败，都调用 `maze_runtime_snapshot` 重读，再更新界面。模型结果与 UI 自己的 -100 段错误码分开；STALE 不自动换新 run 重发。
5. 由 runtime 已有的 20ms 唯一定时入口推进并在 revision 变化时回送；UI 不再建模型推进 timer、不给游戏累计第二份时间、不做 I2C。

注意：main 当前先创建菜单，再初始化 runtime。A 复核生产入口事件只能在初始化成功后可用；自检/初始化失败时须有明确的不可开始提示。B 不重复调用 runtime_init。

### P3：生命周期与异常回归（B 主测，A 复核）

- 显式 BACK：提交 BACK、重读实际状态；成功后先 detach，再销毁页面，回到独立首页。失败不能只销毁画面假装已经退出。
- 页面临时关闭/菜单整体销毁：所有路径都先解除生产 render 引用再释放对象；detach 会暂停/停采样并保留局面，不能偷偷替换成新开局。重进按实际快照显示，不默认 READY。
- 覆盖重复创建、重复销毁、快速 BACK/重新进入、旧页面的延迟事件、旧 run 意图、请求耗尽/动作失败、输入异常。UI 保持响应，失败信息可见。
