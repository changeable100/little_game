# 黄山派固件编译、烧录与串口验证操作指南

- 版本：v1.0，2026-10-17
- 适用平台：本课程黄山派 SF32LB52，板型 `sf32lb52-lchspi-ulp`，SiFli SDK v2.5.1
- 主流程：Windows PowerShell + 工程生成的 UART 下载脚本 + VS Code SiFli 串口监视器
- 适用工程：当前 course_starter 及沿用同一工程结构的后续版本。其他芯片/板型/工程按其实际生成配置处理。
- 本文是操作说明，不是新的烧录成功或功能通过证据。烧录和实物观察由学生执行。

## 1. 每次操作的顺序

**确认代码版本 → 激活 SDK → 检查环境 → 编译 → 确认实际 COM 端口 → 关闭端口占用 → 烧录 → 打开串口 → 重启并验证 → 保存证据。**

只要换终端，就重新激活 SDK。只要改代码、切换分支或更新工程，就重新编译。烧录前检查这次编译确实成功，不能因为输出目录里还留着旧的 bin 就继续下载。

## 2. 准备软件与硬件

首次操作前准备：Git、可运行项目脚本的 Python 3.8+、已安装工具链的 SDK v2.5.1；用 VS Code 监视串口时还需 SiFli-SDK-CodeKit 扩展。SDK 初次安装见 [T0 环境指南](../../training/T0-环境与仓库.md)，本文不要求每次重新安装。

硬件准备黄山派和支持数据传输的 USB 线。接开发板标记的 **USB-to-UART** 接口，按实物丝印确认，不能只按照片中的左右位置判断。若有外接模块，调整接线前先断电；本轮模型自检不需要另接模块。

本文命令以本机路径为例：

| 项目 | 本机值 | 换电脑时怎样处理 |
|---|---|---|
| 项目根目录 | `D:\course_starter` | 改为实际克隆目录，里面应有 src、project、scripts |
| SDK 根目录 | `D:\SiFli-SDK\v2.5.1` | 改为包含 export.ps1 的目录，不是它的上级文件夹 |
| uv 常见安装目录 | `%USERPROFILE%\.local\bin` | 若 uv 已在 PATH 不用额外安装；找不到时核对安装位置 |
| 编译板型 | `sf32lb52-lchspi-ulp` | 本课程按此板型；不能随意换成名字近似的板型 |
| 串口号 | 之前出现过 COM4 | 每次按系统实际识别结果确认，不能固定照抄4 |

克隆源码不会附带已忽略的固件和 SDK。另一成员在自己电脑上需要安装/激活环境并编译，不能只复制一个 main.bin 当作完整工程。

## 3. 确认项目与代码版本

打开普通 PowerShell，执行：

```powershell
cd D:\course_starter
git status --short --branch
git log -1 --oneline
git rev-parse HEAD
```

记录分支和完整提交号。若工作区有未提交修改，如实写“该提交 + 本地未提交改动”，不要写成纯提交版本。不要为准备烧录使用 `git reset --hard` 丢弃改动。

当前模型自检固件源码为分支 `feat/req-301-maze-model`、提交前缀 `77b15d3`。如果你在其他分支，请先看状态确认没有待处理改动，再决定是否切换；不要把切换命令当作每次都要执行的步骤。

## 4. 在当前 PowerShell 激活 SDK

按顺序执行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned -Force
$env:Path = "$env:USERPROFILE\.local\bin;$env:Path"
. D:\SiFli-SDK\v2.5.1\export.ps1
cd D:\course_starter
```

注意第三行开头是 **英文句点，再加一个空格**，即 `. D:\...`。这是把环境载入当前终端；不能在另一个终端激活后，回到没激活的终端继续下载。

第一行只调整当前 PowerShell 进程，关闭窗口后失效，通常不需要管理员权限。若单位/学校组策略仍禁止运行，保留报错交管理员或教师处理，不反复修改全局策略。

正常激活应显示类似：

```text
Activating SiFli-SDK v2.5.1
Done! SiFli-SDK profile default is active.
```

若出现红色错误，先解决错误，不把后续构建文件的存在当作激活成功。`SIFLI_SDK` 与 PATH 可以这样检查：

```powershell
$env:SIFLI_SDK
Get-Command python, scons, arm-none-eabi-gcc, sftool
```

预期 SDK 指向真实 v2.5.1，命令都能定位。若 `uv was not found`，先运行 `Get-Command uv`，核对上一段 PATH 和安装情况；不需要为这个错误修改产品代码。

## 5. 检查环境并编译

仍在同一个 PowerShell，先检查：

```powershell
python scripts/check_env.py
```

必需项应全部通过。然后执行：

```powershell
python scripts/build_firmware.py
$LASTEXITCODE
```

确认脚本明确打印“编译成功”，且紧接着查询的返回码为 `0`。它内部在 project 中调用 SCons，当前默认板型及输出目录为：

```text
sf32lb52-lchspi-ulp
D:\course_starter\project\build_sf32lb52-lchspi-ulp_hcpu\
```

完整编译日志在 `build/last_build.log`，每次构建会更新它。失败时立即复制到本次证据目录并保留首条有效错误；修复后新增一份重测记录，不能覆盖先前失败。

首次或源码变动后不要省略此步骤。只有明确核对了已有产物的版本和哈希、确认就是待测版本时，才可复用已有产物。编译成功只证明生成了目标固件，不代表传感器、屏幕或游戏通过。

## 6. 检查下载文件是否齐全

本机当前输出中应能找到：

```text
uart_download.bat
sftool_param.json
main.bin
bootloader\bootloader.bin
ftab\ftab.bin
```

可以执行：

```powershell
$taskOutputDir = 'D:\course_starter\project\build_sf32lb52-lchspi-ulp_hcpu'
Get-Item "$taskOutputDir\uart_download.bat", "$taskOutputDir\main.bin", "$taskOutputDir\bootloader\bootloader.bin", "$taskOutputDir\ftab\ftab.bin"
Get-FileHash "$taskOutputDir\main.bin" -Algorithm SHA256
```

文件应存在且长度非零。把文件哈希与源码版本一起记录；哈希只用于识别产物，不证明功能正常。

当前生成的下载脚本会下载 bootloader、main、ftab，具体地址由工具生成。**运行完整生成脚本，不要从旧截图抄地址、只烧 main.bin 或修改生成脚本来凑成功。** 后续工程可能有更多镜像，按那次完整构建输出执行，不把本节三个镜像写死为所有工程通则。

## 7. 连接板子并确认 COM 端口

1. 数据线连接电脑和板子的 USB-to-UART 口。
2. 打开 Windows 设备管理器，查看“端口（COM 和 LPT）”。记录串口设备名称和 COM 编号。
3. 不确定哪个设备是板子时，先保存已有日志，再拔插数据线，对比消失/出现的设备。不要把拔插后自动连接才开始的日志当成完整上电日志。
4. 若没有新设备，先换确认可传数据的线和电脑 USB 口，再检查驱动/设备状态。COM 端口不存在时不要反复修改固件。

可选的端口查询命令：

```powershell
Get-CimInstance Win32_SerialPort | Select-Object DeviceID, Name
```

若命令没列出设备，以设备管理器及实际插拔识别为准。之前本机识别到 `COM4 - wch.cn`，这只是历史记录。

## 8. 关闭串口占用，再烧录

在 VS Code 串口监视器点击 **“断开”**，并关闭其他占用同一端口的串口工具。下载器与串口监视器不能同时占用该 COM 口。

回到已激活 SDK 的 PowerShell：

```powershell
cd D:\course_starter
.\project\build_sf32lb52-lchspi-ulp_hcpu\uart_download.bat
```

脚本提示：

```text
please input the serial port num:
```

**只输入实际端口的数字部分**。例如实际是 COM4，就输入 `4` 再回车；不要输入 `COM4`，因为当前 bat 会自行加上 `COM` 前缀。这个交互规则只针对已经核对的当前 Windows bat；其他工具按它自己的提示填完整端口。

观察下载器对所有镜像的处理结果。保存完整输出，确认没有连接、写入或校验失败，并且完整下载正常结束。`uart download`、`com4` 等标题/端口回显不算成功；窗口消失或命令返回也不能单独证明烧录成功。输出中的具体成功文字随 sftool 版本变化，不凭空要求某个固定英文句子。

下载过程中保持连接，不同时启动另一个烧录工具。若等待连接超时，先按故障表排查并保存原错误；需要进入下载模式时按本板官方操作或下载器提示执行，不猜按键组合或短接引脚。

## 9. 使用 VS Code SiFli 串口监视器查看启动

烧录结束后再打开/连接监视器：

| 设置 | 当前项目值 |
|---|---|
| 端口 | 第7节确认的实际 COM 号 |
| 波特率 | `1000000` |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验 | 无（none） |
| 查看方式 | String/文本，便于阅读；需要发送 shell 命令时用终端模式 |

本机 CodeKit 1.4.3 的默认串口参数就是上述8N1与1000000，其他版本以实际设置为准。不能将外设 UART 示例的115200误用为本项目的调试串口波特率。

连接后可能已经错过一次性启动输出。先做好保存准备，再采用下一节的重启方法，以取得从启动到循环的完整记录；看到持续 rgb 日志说明应用正在运行，但仍应核对 APP 版本与本次自检要求。

## 10. 怎样重启并捕获完整日志

### 方法一：固件提供的 reboot 命令

当前项目已经通过真实 `help` 输出确认支持 `reboot`。在监视器切到终端模式，先输入：

```text
help
```

确认能收到命令列表，里面有 `reboot - Reboot System`，再输入：

```text
reboot
```

每条命令输入后回车，保持串口连接并保存随后全部启动内容。其他固件先看自己的 help；没有 reboot 时不能假定存在。发送命令没有响应时先核对终端模式、发送换行和端口，不把命令显示在屏幕上当作板子已执行。

### 方法二：实体复位或明确的上电操作

使用板上已确认丝印和用途的 RESET/RST 按键短按复位；不确定哪个按键时先查板级说明或拍照确认，不能把电源键长按当作通用复位操作。只有单一 USB 供电、无额外电池或外部电源时，拔掉供电再插回才构成断电重启；USB串口重连可能错过最初输出，因此优先采用监视器保持连接的重启方式。

### 关于监视器的“复位”按钮

本机 CodeKit 1.4.3 实现是通过 DTR/RTS 发送复位脉冲，再恢复打开串口时的控制线状态，并记录 `Reset pulse sent.`。默认 DTR=true、RTS=false、脉冲100ms，**消息只证明工具发送了控制信号，不证明板子已复位**。效果取决于实际板卡连接与设置，本项目已经遇到点击后没有重新启动日志的情况。

因此，遇到按钮无效时使用经过 help 确认的 reboot 或已确认的实体复位键。不要因为按钮无效就重新写产品逻辑、任意切换DTR/RTS或认定板子损坏。“刷新”是端口列表相关操作，也不等于重启设备。

## 11. 怎样判断这次操作通过

通用的四层判断：

1. **构建通过**：本次构建正常结束，版本/板型正确。
2. **下载通过**：完整镜像下载成功，保留下载输出。
3. **启动通过**：看到本次固件对应的版本、启动信息，没有导致流程停止的异常。
4. **功能通过**：按本版本测试计划操作，核对实际现象和逐项结果。屏幕、传感器、灯光等要有真实证据。

后续固件可能更改 APP 名称、版本和日志，按当次实现与 TC 判断，不能把旧版本的字符串硬套到新功能。

### 当前模型自检版的具体判据

源码提交 `77b15d3`、APP v0.2.0，主程序哈希在 `evidence/M2/maze_model/README.md`。此版本启动应包含：

```text
[course_starter] v0.2.0 boot ok
Hello world!
[maze:selftest] TC-301 start-calibrate PASS
...中间仍须核对实际的每一项输出，省略号不是固件日志...
[maze:selftest] summary PASS failures=0
[course_starter] rgb -> red
[course_starter] rgb -> green
[course_starter] rgb -> blue
```

共有24个自检场景，每项都应PASS且汇总 failures=0，之后RGB按红绿蓝循环。如果任何一项FAIL，main会停止RGB演示并输出模型自检失败提示；先保存失败日志，停止宣布通过。不能只截最后一条PASS而遗漏前面失败内容。

这版还没有游戏界面、正式关卡或真实 IMU 控制，小球不会显示在屏幕上；本轮只核对启动自检及RGB基线。先前v0.1.0只有Hello与RGB，若新烧录后仍是v0.1.0，先检查源码分支、旧产物、下载结果和实际端口。

## 12. 保存证据与交接记录

当前模型阶段建议保存到 `evidence/M2/maze_model/`。在项目根目录可以先创建目录，未来其他功能按对应里程碑和模块另建目录：

```powershell
New-Item -ItemType Directory -Force .\evidence\M2\maze_model | Out-Null
```

每轮使用实际日期及不同序号命名，保留失败与重测，例如 `boot_log_YYYY-MM-DD_run01.txt`、`boot_log_YYYY-MM-DD_run02.txt`；把日期换成你实际执行日期。日志使用 UTF-8 文本，尽量导出或复制可阅读的原文，不用截图替代所有文本证据。

建议同时留存：

- 本次构建原始输出、完整下载输出、从boot到自检结束的串口原文。
- 对应提交/分支及是否有本地改动、板型与SDK、main.bin的SHA256。
- 实际COM号、波特率、执行人、实际时间、步骤、预期、实际、通过/失败/未执行。
- 功能需要的照片或短视频。大视频不强制加入Git，按课程提供可访问归档链接。

监视器有导出/保存功能时按实际界面使用；没有时从终端复制完整输出并保存文本文件。导出前检查没有筛掉关键启动或FAIL行；本机监视器日志有容量上限，持续运行后旧启动行可能滚出，及时保存。错误/失败保留后才清空显示并开始新一轮。

可复制以下记录模板，不能提前填PASS：

```text
执行人 / 实际时间：
源码分支 / 完整提交 / 本地改动：
板型 / 板卡标识 / SDK版本：
固件文件名 / 长度 / SHA256：
COM号 / 波特率：
重启方式（reboot/已确认实体复位等）：
构建结果 / 下载结果：
测试用例 / 预期 / 实际：
结论（通过/失败/未执行）与未覆盖项：
构建 / 下载 / 串口 / 照片证据路径：
```

将真实证据保存后告诉agent具体目录。agent读取后再补测试报告、manifest的physical_verification和`hw(...)`证据提交。文档示例和主机自检输出均不能冒充这次板上证据。

## 13. 常见问题排查

| 现象 | 首先检查 | 下一步 |
|---|---|---|
| export.ps1报“禁止运行脚本” | 当前PowerShell执行策略 | 按第4节只设置Process范围RemoteSigned；受组织策略限制则保留错误求助 |
| 改到D盘仍无法运行export | 与当前盘符无关，是否仍报策略错误 | 按第4节，不重复切目录掩盖根因 |
| uv/scons/ARM编译器/sftool找不到 | PATH及是否在同一个已激活终端 | 核对export成功状态和Get-Command；不要手工从不同SDK拼工具 |
| check_env提示SDK缺失 | SIFLI_SDK及version.txt实际位置 | 进入正确SDK根目录激活，不随意重装工程 |
| 编译失败但bin还在 | 本次脚本返回码、第一条有效错误 | 保留完整日志，停止烧录旧产物，修复后重新编译 |
| 编译有warning | 判断是警告还是导致退出的错误 | 保留原文和退出码；不要删功能或屏蔽告警凑通过 |
| 找不到COM口 | USB-to-UART接口、数据线、USB端口、设备驱动 | 对比插拔，查看设备管理器状态；未识别前不改应用代码 |
| 串口打不开/Access denied | VS Code和其他工具是否仍占用 | 断开同一COM的所有监视器，确认实际端口再试 |
| 下载等待连接超时 | 端口、占用、供电、板卡模式、工具完整输出 | 按实际板型说明进入下载模式，保留失败记录，不猜按键组合 |
| 下载结束但没有日志 | 监视器是否重新连接、1000000及8N1、是否错过启动 | 先连接再用已确认方式重启；不把无日志直接判定为烧录失败 |
| 串口乱码 | 调试串口波特率、文本/HEX模式、是否连接正确设备 | 当前项目用1000000；核对8N1和String显示 |
| 只有循环日志，没有boot ok | 启动行是否已滚出、是否连接过晚 | 保存现有内容，再在已连接状态下重启取完整日志 |
| 软件复位按钮没有效果 | 复位脉冲不一定连接到MCU复位 | 按第10节help/reboot或确认实体键，不依赖按钮提示 |
| 输入reboot没有响应 | 是否支持该命令、终端模式、发送换行 | 先help确认；核对发送/接收，不擅自发送寄存器操作 |
| 烧录后仍显示旧APP版本 | 源码分支、是否重新编译、端口、下载是否完整成功 | 对照提交及产物哈希，保留证据后重走构建/下载 |
| 有任意自检FAIL | 完整自检日志和对应源码提交 | 保存失败，交agent分析并修复，按同判据追加重测 |
| 只有RGB、没有迷宫画面 | 本版本是否实现UI | v0.2.0是模型自检版，先按版本范围验收 |

## 14. VS Code操作路线与其他系统

若使用 CodeKit 的图形编译/烧录功能：用 VS Code 打开包含src与project的项目根目录，确认实际使用的SDK v2.5.1、板型和端口；编译成功后关闭监视器，再运行扩展的烧录功能，最后打开监视器。菜单名称随扩展版本变化，按其实际功能定位，不把“点击成功”当成下载或功能成功。CLI路线和GUI路线二选一执行同一轮下载，不能同时占用端口。
