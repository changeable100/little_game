## 首版交付内容

真实XYZ坐标、三维球体与平台/墙/坡道接触；固定透视相机和少量低多边形模型。先做一条短赛道，包含平地、斜坡、窄桥、挡墙与一个检查点；掉落后可复活，形成开始/校准/游玩/暂停/掉落/复活/通关/重开的完整闭环。复用中文菜单和IMU，主视图用专门的少量图元/像素缓冲渲染，不给每个三角形创建LVGL对象。

物理重点为加速度与速度连续、球的转动/角速度、接触法线方向的反弹、切向摩擦和滚动阻力；碰撞和画面统一使用三维几何。首版限定一颗球与静态几何，使测试集中在碰撞感与稳定性。系数作为可调参数，定量自检及学生真实手感共同验收，不以“看着像”替代正确碰撞。

## 已确认的迟帧处理与后续调度目标

| 项目 | 初始方案 |
|---|---|
| 物理积分 | 固定5ms小步；方案A物理任务目标10ms唤醒一次，每次按真实累积时间推进 |
| 短时物理迟帧 | 实际间隔≤250ms可有界补算，最多50个5ms子步，保留不足5ms余量；不把250ms作为一次大积分 |
| 物理严重中断 | >250ms自动转可恢复暂停，保留现场与中断时长；该次未模拟区间不计关卡有效用时，不静默截短后声称完整推进 |
| 显示慢帧 | 100～250ms不再触发旧TIMING结束；显示继续消费最近完整快照，按负载降帧，物理保持独立 |
| 长时间画面无更新 | 显示心跳超过500ms则自动暂停，避免盲玩；恢复需新鲜输入与明确继续操作 |
| 输入有效性 | 保留传感器有效/时序/会话检查；显示迟帧容错不等同接受过期传感器数据 |
| 用时 | 累计实际完成模拟的RUNNING时长；等待/校准/暂停不累计，丢失模拟区间另列诊断中断时长；这是对旧需求的明确修订候选，不伪称旧测试语义未变 |

以上数字是初始工程门限，不是板端性能承诺；必须先更新需求/TC，保留原100ms失败/旧测试历史。用户已允许放宽，但“放宽”不能演变成关闭过期/非有限值/严重卡死保护。正常操控仍以低延迟为目标。

## 分批交付与验收

1. **P0迟帧策略与时钟测试**：先在现有工程验证短迟帧容错和可恢复暂停。覆盖100/104/108/200/250/251ms、单调时钟回绕、真实用时/中断时长、暂停/继续与新鲜输入。新的判据经本计划确认后写入docs/01～03；原100ms判据与失败记录保留为旧版本，不事后改成“当时通过”。P0可先交付独立固件，不等待完整3D。
2. **P1纯物理与真3D最小原型**：新3D类型明确位置/速度/角速度/姿态、接触/落地/掉落/检查点和请求/会话版本；不把Z藏在旧二维坐标。球对平面/斜坡/盒体/边角的法线、穿透修正、恢复系数与摩擦可测试；高速防穿透采用有界小步及必要运动扫掠。先验证静止稳定、斜坡滚动、碰墙反弹/切向滑动、能量不无故增加、掉落复活。新增板上纯逻辑自检输出PASS/FAIL。
3. **P2线程与显示闭环**：方案A通过有界操作队列与完整快照通信，物理任务独占模型；LVGL仅在UI线程访问。当前IMU采样工作任务继续独占设备，同一时刻只允许一个游戏会话，旧2D与新3D不同时抢采样。固定相机可以缓存静态场景/深度，动态球按遮挡正确合成；初期尝试低分辨率3D视口和少量多边形，依据实测调整显示目标，不能预先承诺FPS。CPU/堆/PSRAM空闲、每步/每帧耗时与输入延迟需实际测量。
4. **P3手感调参与扩展**：学生真机验证惯性、反弹、摩擦、斜坡、窄桥掉落、复活/中文提示和中断恢复，保留失败/重测；基础闭环通过后再增加关卡和移动障碍。

REQ-503（迟帧/时钟）和TC-503已正式登记并完成软件验证；REQ-501（三维世界/渲染）、REQ-502（接触/手感）、REQ-504（线程/生命周期）及TC-501/502/504在P1/P2实现前细化登记并运行追踪。实现前查所用SDK/RT-Thread接口与原SConscript风格，优先新增模块，不擅改工程骨架或配置。
