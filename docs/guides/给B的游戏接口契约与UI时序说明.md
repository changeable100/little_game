## 3. 快照 maze_snapshot_t

| 字段 | 真实C类型 | 含义和 B 的使用规则 |
|---|---|---|
| `run_id` | `uint32_t` | 局号；START/RESTART/BACK成功时加1。UI意图携带用户操作所基于的局号 |
| `revision` | `uint32_t` | 模型版本；状态变化、校准完成、有效非零step时递增。可跳过相同版本的重复绘制 |
| `level_id` | `uint32_t` | 当前地图ID，与传给UI的关卡id应相符 |
| `state` | `maze_state_t` | 游戏状态，决定页面/按钮/提示 |
| `input_status` | `maze_input_status_t` | 模型所记录的输入状态，不是传感器设备的实时查询 |
| `error_code` | `maze_error_t` | 模型错误原因；需结合返回值及state判断 |
| `ball_x` | `float` | 小球圆心x，单位格，向右为正 |
| `ball_y` | `float` | 小球圆心y，单位格，向下为正 |
| `ball_radius` | `float` | 圆半径，当前0.20格；UI从快照读取用于绘图 |
| `elapsed_ms` | `uint32_t` | 只累计RUNNING的已接受模拟时间，毫秒；暂停/通关不累加 |

初始化成功后：run_id=0、revision=1、state=READY，球在起点格心、时间0、输入NOT_READY、错误NONE。快照由 `maze_game_snapshot()` 按值复制；B 不持有模型内部snapshot指针、不修改返回快照来改变游戏。渲染函数若需要跨调用保存内容，应复制数据，不保存调用者临时栈地址。

生命周期内revision不回绕，达到UINT32_MAX后模型拒绝后续变更。run_id和请求号也不回绕。整个游戏实例重新初始化后这些编号会从初值开始，A必须同步清理旧UI回调/意图生命周期，B不能拿上一个实例的revision过滤新实例。当前没有额外session_id字段。

## 4. 状态、输入状态与错误类型

### 4.1 maze_state_t

| 枚举 | 当前隐式值 | 意义/界面建议 |
|---|---|---|
| `MAZE_READY` | 0 | 待开始，显示开始入口 |
| `MAZE_CALIBRATING` | 1 | 等待A完成真实校准，显示保持平稳提示；不能显示已运行 |
| `MAZE_RUNNING` | 2 | 正在运行，可暂停 |
| `MAZE_PAUSED` | 3 | 暂停，位置/时间冻结；可继续或重开 |
| `MAZE_WON` | 4 | 通关，位置/用时冻结；可重开或返回 |
| `MAZE_ERROR` | 5 | 明确错误，按error_code提示；恢复由A处理 |

当前没有独立LOST/死亡状态，也没有模型菜单页状态。B可有自己的页面导航状态，但不能用其代替模型的游戏状态。未识别枚举应显示明确错误/安全页面，不默认当RUNNING。

### 4.2 maze_input_status_t

| 枚举 | 值 | 含义 |
|---|---|---|
| `MAZE_INPUT_NOT_READY` | 0 | 初始化/新局/返回后，尚未确认可用输入 |
| `MAZE_INPUT_VALID` | 1 | 当前局校准完成或有效step记录的状态 |
| `MAZE_INPUT_FAILED` | 2 | RUNNING的输入参数无效，模型进入输入错误 |

它不是传感器新鲜度证据。`maze_input_t` 目前没有时间戳、序列号和校准局号；A的输入集成层必须检查来源、新鲜度和当前局，不能把校准前或旧局缓存输入直接送进模型。B不读取I2C，也不依据这个枚举宣布传感器采样频率达标。

### 4.3 maze_error_t

| 枚举 | 值 | 产生情形 |
|---|---|---|
| `MAZE_ERROR_NONE` | 0 | 当前无模型错误 |
| `MAZE_ERROR_LEVEL` | 1 | 初始化地图检查失败，实例没有可运行关卡 |
| `MAZE_ERROR_INPUT` | 2 | RUNNING中NULL/失效/NaN/Inf/超出[-1,1]的输入 |
| `MAZE_ERROR_TIMING` | 3 | RUNNING中dt_ms超过100 |

时间错误不自动把input_status改为FAILED；UI必须同时看state/error_code。计数耗尽是函数返回 `MAZE_EXHAUSTED`，当前不会另写入error_code或自动切ERROR；A应上报明确集成故障、停止操作并安全重建实例。不要只看快照中没有ERROR就忽略失败返回。

## 5. 操作意图 maze_action_t

| 字段 | 真实C类型 | 要求 |
|---|---|---|
| `action` | `maze_action_kind_t` | 下表的操作枚举 |
| `expected_run_id` | `uint32_t` | 用户所见快照的run_id；旧局请求拒绝 |
| `request_id` | `uint32_t` | 非零；在整个模型实例生命周期中严格递增，重开/返回/重建UI对象不能擅自归1 |

请求号生成器由A的意图适配层统一提供，B每次新操作领取新号并携带显示所基于的局号。重复投递同一个请求不得换号伪装为另一个用户动作。拒绝动作不会更新模型的last_request_id；已接受动作才记录该号，但B仍按统一生成器递增，不依赖此细节复用号码。

| action枚举 | 值 | 允许状态 | 接受后的行为 |
|---|---|---|---|
| `MAZE_ACTION_START` | 0 | 仅READY | run_id+1；位置/速度/时间复位，错误清空、输入NOT_READY，进入CALIBRATING |
| `MAZE_ACTION_PAUSE` | 1 | 仅RUNNING | 进入PAUSED，**两轴速度清零**；位置/elapsed_ms保留 |
| `MAZE_ACTION_RESUME` | 2 | 仅PAUSED | 进入RUNNING，保留位置/elapsed_ms；从暂停后的零速度继续受输入加速 |
| `MAZE_ACTION_RESTART` | 3 | 任意已成功初始化的模型状态 | 新局号，位置/速度/时间复位，进入CALIBRATING |
| `MAZE_ACTION_BACK` | 4 | 任意已成功初始化的模型状态 | 新局号使旧操作/校准失效，复位球和时间，进入READY；UI可返回菜单 |

“任意状态”仍受参数、局号、请求号与计数上限检查，不包含失败初始化后无level的对象。重复START在校准/运行中返回WRONG_STATE；同请求重复RESTART返回STALE，但**用新请求号主动再次RESTART会再开一局**，模型不会替UI合并所有点击。B按最终交互规则管理按钮，不能假定所有连点都自动忽略。

START/RESTART不是“校准完成”。只有A核实真实输入校准完成后，才在UI线程调用 `maze_game_calibrated(game, captured_run_id)`。B不得在开始按钮回调中立即假装校准成功。

### 意图回调类型

```c
typedef maze_result_t (*maze_action_sink_t)(void *context,
                                          const maze_action_t *action);
```

当前契约要求它**同步、非阻塞且在UI/模型所属线程调用**。A提供实际适配，B只保存回调与context并发送意图。方案A不需要独立游戏任务和动作队列，因此当前没有“队列忙”返回码；旧任务书中的队列忙是备选方案讨论，不代表本版实现。若后续引入队列，先变更契约和用例。

调用返回OK后取新快照再更新控件；不要在发送前自行修改游戏状态。适配实现和B的 `maze_ui_create/render/destroy` 尚未落地，不应在现有源码中搜索一个已经能用的maze_app入口。

## 6. 关卡 maze_level_t

| 字段 | 真实C类型 | 定义 |
|---|---|---|
| `id` | `uint32_t` | 地图标识，与快照level_id关联 |
| `cols` | `uint8_t` | 列数1～16 |
| `rows` | `uint8_t` | 行数1～16 |
| `cell_count` | `uint16_t` | 必须恰好等于cols×rows，最大256 |
| `cells` | `const uint8_t *` | 行优先一维只读数组，0=PATH、1=WALL，不接受其他值 |
| `start_col` / `start_row` | 各`uint8_t` | 起点格索引，从0开始，在范围内且为PATH |
| `goal_col` / `goal_row` | 各`uint8_t` | 终点格索引，从0开始，在范围内且为PATH，不能和起点重合 |

索引：`cells[row * cols + col]`。**关卡结构本身与cells数组都必须比游戏实例活得久**，推荐static const；不能把函数中的临时数组/临时关卡地址返回后给模型。运行期间不修改cols/rows/cells，也不释放或切换其内存。

格类型在头文件中声明为 `enum maze_cell`：`MAZE_CELL_PATH = 0`、`MAZE_CELL_WALL = 1`；cells实际存储类型仍是 `uint8_t` 数组。B可使用枚举符号初始化数组，不另加起终点编码。

模型会检查上述尺寸、长度、格类型及起终点条件；C指针并不能让模型检查数组实际分配长度，B必须保证cells至少有cell_count个元素。模型没有BFS/可达性检查；无通路的地图仍可能通过模型安全检查，B需另做可达性自检和真实可玩性测试。

正式地图由B实现，本版 `maze_selftest.c` 的9001～9004是测试标识，不能直接当作正式产品关卡。为了可读性B可以绘制起终点标记，但底层对应格仍是PATH，不能往cells里引入未经约定的新格类型。

## 7. 半径、坐标与屏幕换算

- 坐标原点在整个地图左上角，x向右、y向下，单位都是“格”，不是像素或毫米。
- 格 `(col,row)` 占据 `[col,col+1] × [row,row+1]`。起点圆心为 `(start_col+0.5f, start_row+0.5f)`。
- 圆半径0.20格，直径0.40格。不能把0.20当直径，也不能让画出的球大小与模型判定不一致。
- UI采用正方形格子的统一缩放s（像素/格），游戏区偏移为ox/oy，圆心像素为 `(ox + ball_x*s, oy + ball_y*s)`，半径像素为 `ball_radius*s`。
- 若LVGL对象定位使用左上角，先减半径：`left=ox+(ball_x-ball_radius)*s`、`top=oy+(ball_y-ball_radius)*s`，宽高约为 `2*ball_radius*s`；再按B统一的像素舍入规则取整。
- UI墙边框/阴影若占额外可见面积，不应误画成模型不存在的障碍。必要时把边框画在格子内部，或在视觉说明中明确；不能为美术效果另做一套碰撞。

例如s=30像素/格，仅作换算示例：半径6像素、直径12像素。它不是要求正式界面必须用30像素格子，正式布局由B结合可用游戏区设计。

## 8. 每步时间、最大位移与运动规则

| 层级 | 时间 | 单轴最大位移上界 | 合位移上界（双轴同时最大时） |
|---|---|---|---|
| 一个内部子步 | ≤5ms | ≤0.015格 | ≤约0.021214格 |
| 目标的一次UI推进 | 约20ms，实际由单调时钟差提供 | dt=20ms时≤0.06格 | ≤约0.084853格 |
| 一次调用允许的最大推进 | 100ms，最多20子步 | ≤0.30格 | ≤约0.424265格 |

这些是根据每轴速度上限3格/秒推导的上界，不是测试测出的实际位移；起步加速、阻尼和碰撞通常让位移更小。合速度上限约4.242641格/秒，不能误写成3。

每子步按各轴先更新速度，再计算位置：

```text
dt = 子步毫秒 / 1000
v = clamp(v + dt * (12 * tilt - 4 * v), -3, 3)
candidate = position + v * dt
```

按x再y分别处理碰撞。dt不是任意大的参数，RUNNING中超过100ms就报时间错误，不做“截成100ms继续”或无上限追赶。dt为0时有效输入不会移动/计时/改revision，但**仍先校验输入**，传入无效样本仍会进入输入错误。非RUNNING状态的step直接OK且不修改快照，前提game/level有效。

### 8.1 碰撞边界

1. 墙格是轴对齐方块，球是圆。用圆心到墙格矩形最近点的距离判断；距离平方严格小于r²表示相交，相切允许。
2. 地图外是不可通过边界，即使最外圈数据为PATH也不能出界。圆心必须满足 `r ≤ x ≤ cols-r`、`r ≤ y ≤ rows-r`。
3. x候选相交时保留该子步旧x，x速度归零；再用实际采用的x处理y。y同理。**不是弹性反弹，也不是精确贴到碰撞接触点**，因此墙前可能保留小于一步移动量的间隙。
4. 一轴碰撞不强制停止另一自由轴，允许沿墙滑动；B不再次把球吸附到格心或推离墙。
5. 小步积分与限速用于防跨越一格厚墙；正式迷宫仍需B核查通道净宽和整体可达性，不能只凭单元格通路宣称实际能通过。
6. 小球**圆心进入终点格**即WON，并不要求整个圆都进入终点，也不要求圆心到达终点格中心。该子步结束后停止，剩余dt不继续模拟。

上述是当前代码语义。浮点显示舍入不改变逻辑边界；B不能为消除像素误差直接改模型位置或放宽碰撞条件。

## 9. elapsed_ms 的准确计时语义

**暂停时停止累计。** 模型不读系统时钟，elapsed_ms只由已接受的RUNNING子步增加，单位ms，和UI重绘次数无关。

| 情况 | 时间怎样处理 |
|---|---|
| 初始化、START、RESTART、BACK | 归0 |
| CALIBRATING | 不累计 |
| RUNNING有效step | 每实际执行的子步加该子步ms，即使顶着墙不动也计时 |
| PAUSE成功 | 保留当前值，不归0；暂停期间step不增加 |
| RESUME成功 | 从保留值继续，暂停时长不得混入下次dt |
| WON | 加上到达终点的那个子步，丢弃本次剩余dt；之后冻结 |
| 输入失效或dt>100ms | 本次不增加时间，转ERROR；错误后冻结 |
| 达到UINT32_MAX | 饱和，不回绕，约49.7天；不等于计时精度保证 |

例：运行step(20)后20ms → PAUSE → 暂停期间调用step(100)仍20ms → RESUME → step(20)变40ms。即使界面暂停了五分钟，继续时也不能把五分钟作为dt传入。

B只格式化，例如整秒 `elapsed_ms / 1000u`、百分秒 `(elapsed_ms % 1000u) / 10u`。禁止在界面维护另一份游戏秒数、每次render加20ms、用显示帧数推算用时或自行按“墙上时间”修正模型计时。显示运行20ms而整秒仍为0是正常取整结果。

当前没有生产UI时钟，所以本节不声称已实现真实时钟精度或测得稳定刷新周期。

## 10. UI线程真实可用的模型入口

完整声明在 `maze_game.h`。这些函数均无锁，调用方必须在**同一个模型所属/UI线程**顺序调用；不从IMU任务、ISR、shell或其他线程直接修改同一实例。模型使用静态/长生命周期对象，不调用malloc。

### 10.1 地图检查和初始化（A）

```c
maze_result_t maze_game_level_check(const maze_level_t *level);
maze_result_t maze_game_init(maze_game_t *game, const maze_level_t *level);
```

level_check仅返回OK/INVALID，不做可达性验证。init成功得到READY快照；失败若game非NULL，会将该对象清零并设ERROR/LEVEL，level为空，不能直接RESTART修复，须A提供合法地图后重新初始化。game==NULL只返回INVALID。不能对一个正在用的实例随意重复init，否则旧引用及编号语义失效。

### 10.2 操作和校准完成（A适配，B发意图）

```c
maze_result_t maze_game_action(maze_game_t *game,
                               const maze_action_t *action);
maze_result_t maze_game_calibrated(maze_game_t *game, uint32_t run_id);
```

action的允许状态见第5节。calibrated仅接收当前局且正处CALIBRATING的完成通知；旧局为STALE，错误状态为WRONG_STATE。模型不会在函数内采集或完成硬件校准。

### 10.3 游戏推进（A统一调度）

```c
maze_result_t maze_game_step(maze_game_t *game,
                             const maze_input_t *input,
                             uint32_t dt_ms);
```

`maze_input_t` 的字段是 `float tilt_x`、`float tilt_y`、`bool valid`。A提供已校准、已换成屏幕方向的有限归一化输入，每轴[-1,1]。模型不理解原始g、角度、寄存器值或I2C错误码。正tilt_x向右、正tilt_y向下，实际传感器轴映射由A真机验证。

RUNNING中NULL或无效输入返回INVALID并进入ERROR/INPUT；dt>100进入ERROR/TIMING。game为空或没有有效level则只返回INVALID。非RUNNING直接OK、状态不动，因此**OK不等于小球一定移动或时间一定增加**。

### 10.4 读取快照（A复制，B渲染）

```c
maze_result_t maze_game_snapshot(const maze_game_t *game,
                                 maze_snapshot_t *snapshot);
```

复制当前快照到调用者提供的对象，OK不增加revision。任何参数NULL返回INVALID。调用前必须已有一个经过init的有效存储对象，不能用未初始化内存。初始化地图失败后仍可读取ERROR快照以显示错误。没有等待、堆分配或内部线程通信；这也不意味着它能安全地与另一个线程同时写模型。

## 11. 返回值与 UI 反馈

| 返回值 | 数值 | 含义 | B/A的处理 |
|---|---|---|---|
| `MAZE_OK` | 0 | 调用接受/读取成功；step也可能是非运行态或零dt的无动作 | 读新快照再显示，按状态判断结果 |
| `MAZE_INVALID` | -1 | 参数/地图/输入/时间不合法，是否改变状态取决于入口 | A记录原因，读快照；B按快照提示，不能直接当作已成功 |
| `MAZE_WRONG_STATE` | -2 | 当前状态不允许该操作/校准完成 | 保持真实状态，刷新按钮与提示 |
| `MAZE_STALE` | -3 | 旧局、已接受过或更旧的请求号 | 丢弃迟到操作，取当前快照；不自动改成新局号强行重发 |
| `MAZE_EXHAUSTED` | -4 | run/request/revision计数达到限制，不能继续指定更新 | A停止相关操作并安全重建生命周期；B显示集成错误，不等待自动ERROR状态 |

动作/校准拒绝不改变模型；RUNNING输入/时间错误会改变成ERROR并归零速度；零dt下的坏输入同样会改变成ERROR。UI不要把所有INVALID当作“状态完全没变”。具体判定顺序以真实实现为准，不能依赖一个同时有多种错误的调用只返回你预期的那一种。

## 12. 谁管理刷新时钟

**由A的集成层管理唯一游戏刷新入口；B管理界面对象与绘制，不建立第二个游戏时钟。** 这是方案A的接入约定，实际LVGL定时器和生产适配尚未实现。

| 工作 | 责任 | 约束 |
|---|---|---|
| 创建/销毁游戏刷新定时器或等价周期入口 | A | 在正确LVGL线程，目标20ms，仅一个有效入口 |
| 单调时间读取、dt换算与上一时刻锚点 | A | 用实际时间差，不固定传20；处理时钟回绕、暂停与重入 |
| IMU采样、有效性/新鲜度判断和受保护复制 | A | 采样方不操作UI；UI回调不等待I2C或耗时校准 |

### 12.1 一次正常回调的顺序（接入约定，不是已有应用函数）

```text
由UI线程周期入口触发：
  A读取单调毫秒时间并计算从上次有效锚点到现在的dt
  A更新锚点（非运行状态也要维护，避免恢复时带入暂停时长）
  A非阻塞取得当前局有效的输入副本
  A在RUNNING需要推进时调用maze_game_step，保留真实dt
  A处理返回值，调用maze_game_snapshot复制结果
  A把快照和同level_id的地图交给B的渲染入口
  B只更新需要改变的LVGL对象
```

这一顺序没有假定 `maze_app_tick`、`maze_ui_render` 或某个SDK定时器已经存在；B应提供实际UI接口，A再接入真实LVGL初始化和调度。UI控件事件与周期回调串行在同一线程处理，不在别的线程加锁后“顺便调用LVGL”。

### 12.2 暂停、继续、校准、重开与时钟锚点

- A在状态切换边界重置或结算锚点。若需要计入上次tick到暂停点击之间的运行片段，先用实际运行片段做有界step，再执行PAUSE；不能把点击后的暂停段算回运行。
- RESUME、当前局校准完成后进入RUNNING、RESTART/START和页面重新进入都应更新锚点；下次dt只覆盖新状态内应计入的片段。
- 周期回调不能把UI阻塞的一长段真实dt截成20/100ms来掩盖卡顿，也不能无限循环追赶。超过100ms应走现有时间错误，记录问题，再由A修复耗时源/调度。
- 校准完成/传感器错误由采样线程上报时，A负责非阻塞通知UI所属线程并核对run_id后再调用模型；生产通知通道目前未实现，B不要在工作线程调用模型凑接入。
- 普通页面重建不等于销毁游戏实例。B不自行重新编号；整个实例需要重建时由A统一清理旧回调、请求生成器和快照缓存。

模型层的暂停冻结已通过自检；真实UI线程时钟及上述状态边界结算没有生产代码和实测，需联调后才能宣称精确计时与流畅刷新。
