## 3. 几何必须能走，画面与碰撞共用数据

用`roll3_scene.c`现有DECK/SLOPE写法构造顶面。OBB的`center`是实体中心，不是路面中心：平平台中心在顶面下移半厚；坡体中心沿负法线移半厚，斜长由真实坡长计算。`axis[0..2]`必须是单位正交右手基，半长严格为正；不要拿歪斜轴、视觉覆盖或互相穿插的盒体掩盖接缝。

当前M3地图局部变换是：

```c
x = u * R3_M1_COS - v * R3_M1_SIN;
y = -u * R3_M1_SIN - v * R3_M1_COS;
/* R3_M1_COS=.5，R3_M1_SIN=.8660254038，z独立。 */
```

地图局部基与相机基不同。不要把u/v草图直接当成世界x/y，也不要为了让新路线朝下就旋转相机或翻转IMU轴。复用完整精度宏；每张预览注明球位置、朝向和路线方向。

相邻坡/台以真实顶面共边衔接，先算端点再出图。沿用已有严格接缝断言，新增连续接缝建议误差不大于0.1mm，另验证曲面端点及切向方向。需要落差时把“有意离地/落点”写入设计与TC；不要让无意高差或重叠台阶冒充难度。路宽除了要大于球直径，还要留出转向与误差空间；几何校验通过不代表可玩。

出生和存档点取稳定承载面内部，球心约为顶面加半径/既有接触余量，离侧壁和边缘有安全距离；不能穿地、悬空或复活后马上再掉落。检查点区域是世界轴对齐包围区，旋转平台里要内缩，不能跨到旁路误触发。`fall_z`低于有效路面且保留合理落下距离。

沿用`r3_bend_profile/height/point`共享剖面生成曲面画面和接触。现有弯是半环，可拉长但会做世界宽度补偿；不要只缩放渲染网格而漏改碰撞梯度，也不要把多段曲面装成一个参数假装支持。当前弯校验包括半宽大于球半径、内半径大于两倍球半径、拉伸为0或1～2、凹深0～0.75m等，直接查生产校验器，别只抄表面数字。

## 4. 终点、护栏和装饰的易错处

绿色终点用真实承载盒，`goal_box_plus_one`填该盒0基索引加1；数组重排后必须复核，不能把护栏或别的平台误设为终点。启用当前交互时`finish_rolls=true`。旧`goal`区域仍要满足世界校验，不能随便填无效区间。只接触上部承载面才应获胜，掠过上方、撞侧壁或接近绿色不能误判。

终点没有道路的边加实体OBB护栏，入口保持畅通，护栏计入16盒预算。旗门、装饰柱、背景台阶和纯美术墙不会阻挡球；凡是玩家以为可站/可挡的地方，要有相符碰撞，或在造型上明确它只是背景。严禁用通关瞬间锁定结果来掩盖墙体穿透测试。

新地图自己的style要对应自身盒体索引：`solid_boxes_from`决定承载棋盘路和实体色盒的分界，`thin_road_mask`按盒索引选薄侧壁。修改路/护栏顺序后同步调整。M3私有`roll3_stage_art.h`依赖其LOCAL宏和坐标，不直接拿给新地图混用。

装饰不能遮挡前方路口、存档点或绿色终点。优先少量大体块和明确边缘，不堆很多细杆、极细棋盘或大量共面面片；不要增加高频逐像素效果、全屏后处理或新字体/大型贴图。固定机位下检查斜侧墙是否挡球；相机跟随不能代替地图本身的可读性。

## 5. B必须交付的验证

1. 路线表：每段的顶面范围/高度/坡向、宽度、盒索引及用途，另列出生、存档、绿色承载盒、护栏、掉落线、装饰面数。先给两种路线的体验和预算权衡，负责人选定后固定验收条件。
2. 板上与主机同源自检：世界合法，出生/复活不穿透，接缝、护栏/入口、检查点与终点不误触发。新增地图用显式world测试，保留原M1/M2/M3判据与用例。
3. 一条从出生开始的5ms连续物理回放：实际经过路线、检查点并进入终点；记录用时、掉落、`limited_steps`等。不能逐段修改球位置来宣称全关通关。构造球位的单元测试可以保留，但必须单独标清用途。
4. 高速与边缘：正冲/斜冲开放边、坡台接缝、曲面进出、护栏和落点；至少覆盖既有0.5/2/5/7.5m/s及接近边缘法向的角度回归，保留真实障碍减速。开放边不得异常清零或耗尽预算，真实护栏不得穿透。
5. 同位置实际SDK主机图：起点、每个关键转向/落点、存档、弯中、终点，普通游玩状态及暂停/结算遮挡检查；逐图看清球、前路、边缘、文字，不只提交生成成功日志。主机图不能写成真机图。
6. 100/50行两档逐像素一致、尾带及越界哨兵，维持原边缘质量阈值和内存预算；比较性能时串行执行，不和SDK编译并跑。新增装饰的开销单独记录，不把主机毫秒换算成板端FPS。
7. 全核心和真实SDK LVGL回归、字体覆盖（改文案时）、原SDK整机编译。出现FAIL保留原输出，再提交修复重测；不调松阈值、删测试或屏蔽警告。当前参考是162项核心，新增有意义用例后数量可以增加。
